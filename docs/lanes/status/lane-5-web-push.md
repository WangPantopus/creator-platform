## Implementation and interface

Creator web registrations use the existing `PUT /v1/growth/devices` route, encrypted session binding, registration revision and per-delivery receipt ledger. Body: `{ installationId, platform: "web", token: JSON.stringify(subscription), permission, registrationRevision }`. The subscription is the browser's endpoint, optional expirationTime and p256dh/auth keys. A granted web registration requires the real creator account. A denied registration or the existing DELETE route can retire its current binding. Native registration semantics are unchanged.

The endpoint must be HTTPS on exactly `fcm.googleapis.com`, `updates.push.services.mozilla.com` or `web.push.apple.com`, with no alternate port, credentials, query or fragment. Unknown push services are unsupported. Invalid P-256 points and malformed auth keys are refused before persistence. Subscriptions and their keys are encrypted; there is no new plaintext endpoint table. Browser key rotation must increase registrationRevision.

`NativeDeliveryProvider` accepts `webPush: { subject, publicKey, privateKey }`. It uses the maintained [web-push library](https://github.com/web-push-libs/web-push) to create aes128gcm ciphertext and VAPID authorization, then submits with an abort signal and redirects disabled. The payload is only `{ notificationId }`, TTL one day. HTTP 201 records acceptance; 404/410 revoke the subscription; a known rejection can retry; an ambiguous response remains unknown and is never blindly repeated. Credential/encryption preparation happens before marking external submission, so a preparation failure is not falsely recorded as an uncertain send.

The optional `webPush.fetch` is the outer-edge gateway seam, used only in scenarios; production defaults to HTTPS fetch. The scenario redirects only an exact synthetic FCM path to its local HTTP server. It independently verifies VAPID signature/audience/expiry, decrypts the body with the synthetic browser's key and rejects extra payload fields. Gateway acceptance is not browser display.
