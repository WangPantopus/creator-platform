## Safety and case procedures

Safety responder is the **W8 safety on-call role**; commercial dispute responder is **W4 commerce on-call**; identity/verification responder is **W1 identity on-call**; license/model responder is **W2 AI on-call**. Human names, escalation channels and staffed hours must be assigned before pilot. Do not claim a response SLA while staffing is absent.

Queue access requires an unrevoked, unexpired `ops_member` with that queue. Open evidence only for a defined purpose; a lease lasts at most 15 minutes. All evidence reads/decisions append access audits. Search supports exact case number; broad private conversation search is absent. Resolve with a reason sent only to the involved recipients. Refunds/verification/pause/license/account changes create durable effect intents, retain `action_pending`, and resolve only after domain receipts. Critical identity/license actions require supervisor membership. Appeals require a different reviewer from the last decision maker.

For a blocked/retry/dead-letter action, inspect the owning domain's receipt/current state first. A current leased supervisor can use Action recovery in the case or POST `cases/:id/effects/retry` with current version/reason/idempotency key. The original effect ID/actor/input/decision version are preserved; repeated commands return the same acknowledgment and do not duplicate the audit. A 30-second case cooldown bounds new retry commands. Recovery cannot turn missing receipts into resolution. `/ops/audits` shows the current operator's own audit metadata; `/ops/metrics` shows authorized supervisor process/worker snapshots, not cross-domain SLO proof.

Reports do not require a grant. Crisis routing does not include paid access. Configure jurisdiction-reviewed help resources and published contact information before enabling external use. W2 calls `recordCrisisReferral` only after actual protocol/resource handling; stable event ID deduplicates counters. Day/region/protocol counts contain no user, creator, message, or conversation identifiers. No evidence-free claim of emergency monitoring, successful referral or annual filing.

W8 commits negative-authority restrictions and deletion tombstones synchronously. W1/W2/W3/W4 must apply denial before access/acceptance/context assembly/delivery and propagate the ordered control boundary. `createTrustRuntime` returns `assertActorAllowed(actor)` and `assertScopeAllowed(actor,creatorId,threadId)` for W1's current configured-backend seams; both also deny restored traffic while replay/purge is pending. ## Privacy worker

Jobs are actor-verified, immutable-scoped and replayable. Delete commits a tombstone before background work. For account jobs, configure dependencies.privacyOwnership(actor) using verified W1 owned profiles before identity removal. W8 stores the bounded UUID snapshot/reference immutably. Bind privacyOwnershipScope(workerPool) to W7 GrowthPrivacyScope; both job and account must match. Missing old snapshots return null rather than a guessed empty set; new verified fan-only snapshots explicitly return[]. Progress-only UPDATE grants protect job identity/scope/verification/ownership. No hook may reconstruct ownership from deleted identity absence.

Each of eight domains independently acknowledges export/purge with stable key `jobId:domain`. Missing hooks become `blocked`. A job is complete only when all required tasks are complete. The trust hook exports/purges its own scoped support/report/feedback data; it never reads arbitrary private threads. Every other owner supplies its own hook.

Worker claims bounded batches with `SKIP LOCKED`, 60-second leases and fencing tokens. Hooks have a 45-second deadline and must split long operations into bounded durable subjobs. A timeout may occur after external success; retry with the same domain/provider idempotency key. Retry uses exponential backoff capped at one hour; after eight attempts the task enters `dead_letter`. Operator first checks the hook/provider receipt and underlying durable state, then enables retry. Do not replace `blocked` or `dead_letter` with a success record.

Twelve-month request/delivery retention uses original evidence expiry; account-wide retention remains Q16/counsel-reviewed. Required ledger retention is supplied by W4 configuration, not invented by W8. Store billing cancellation is separate from deletion, and the UI links to Apple/Google subscription management. Tombstones/job receipts remain for restoration denial pending retention review. Completed export payloads expire after seven days. No downloaded export is created while a domain is incomplete.

## Incident response

1. Triage by correlation ID, release, capability state and fixed route/error code. Logs contain no body, query, token, raw message, private memory or provider secrets. Read case content only through an authorized lease.
2. For suspected isolation or authorization loss, disable affected generation/access through owner controls, preserve redacted IDs/audit evidence, and notify W1/W2/W3. Do not enable fallback owner connections or weaker prompts.
3. For model outage, W2 switches only to an approved/consented provider or pauses AI; keep reports/deletion/support reachable. For payment unknown state, W4 polls provider intent and reconciles ledger before retrying. For calls, W6 provides participant/timing evidence and W4 settles; no client callback proves delivery/refund.
4. For missed scheduler/worker death, restart only the leased worker; expired jobs are reclaimed. Inspect queue age, retry/DLQ and receipts. External success is deduplicated by stable effect ID. Never replay changing amounts or recreating money with a new key.
5. Publish a sanitized status update: affected capability, user impact, known workaround, next update time. No private reason or fan content enters the public incident table. Human responder owns updates and closure.
