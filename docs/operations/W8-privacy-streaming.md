# W8 protected C10 streaming continuation

The coordinator now implements an opt-in `PrivacyHook.stream` contribution in [privacy-export.ts](../../apps/backend/src/modules/trust/privacy-export.ts). Existing inline contributions, original jobs and the40 applied migrations remain unchanged. The stream path stores a small manifest in the existing task `data`/receipt;0052 remains an unapplied reservation for resumable durable chunk checkpoints. No new SQL or broader database privilege is needed by this increment.

An owner supplies a stable `snapshotRef`, content type, ordered asynchronous chunks and a final acknowledgment after complete source exhaustion. Chunks are at most1MiB and start at sequence0. The final acknowledgment must state `complete=true`, `sourceExhausted=true`, the same snapshot, and exact total chunks/bytes/SHA-256. The coordinator independently hashes/counts every chunk, awaits each write for backpressure, verifies the persisted artifact and rechecks actual `privacyTaskAuthority` before writes, seal and acknowledgment. A missing store blocks the task. An invalid/partial contribution fails; a capacity refusal never truncates into success.

Owner work, iterator exhaustion, seal and verification share the existing45-second deadline under the60-second task lease. The cooperative AbortSignal stops further coordinator work; it does not prove cancellation of an external operation. Current lease token/state **and expiry** fence completion. Slow owners must provide durable bounded subjobs; this increment does not claim resumability or completed owner source coverage. The original `jobId:domain` retry key is preserved.

The host passes one reviewed `privacyArtifacts: PrivacyArtifactStore` to `createTrustRuntime`, where both worker and authenticated download service consume it. A required real `privacy_exports` probe, protected storage, fresh-auth verification and each domain's existing readiness probe are necessary. Merely constructing the store or registering a hook does not establish readiness. The current local runtime has no store configured and no owner hook using this new stream contract.

[PrivateFileArtifacts](../../apps/backend/src/modules/trust/private-file-artifacts.ts) provides an opt-in single-host implementation: absolute private0700 server-owned directory, minted opaque references,0600 exclusive attempt files, bounded writes, file/metadata/directory sync, complete SHA verification, no symlink reads and no public URLs. It refuses more than1GiB. Fresh-process reads verify the same stored binding/bytes and yield at most64KiB. The bounded sweep visits at most1000 directory entries/removes at most100 expired artifacts per tick, retaining its directory cursor; seven-day expiry also covers abandoned attempts/orphan bytes. Worker drain closes its cursor. This is not approved encrypted off-site/object storage, replication, WAL or an RPO/RTO claim. The host must retain this private directory through process restarts and supply its reviewed storage/retention/backup policy.

`GET /v1/trust/privacy/jobs/:id/download/:domain` opens only a manifest attached to that account's complete, unexpired export. W1's existing current Pantopus session proof must be fresh within five minutes. Every streamed part rechecks current actor and permitted job/scope; progress remains available after denial while payload access remains closed. Express/Next forward the bytes with backpressure, `no-store`, `nosniff`, fixed attachment names and disconnect cancellation. The JSON export remains available as its original manifest/inline format. Web offers protected domain files only after the complete job's actual stream receipt exists, plus a canonical reauthentication link for current-session configuration. Native file/save consumers and actual owner/binary exports remain unverified.

Interrupted transfers close the connection and get a separate bounded HTTP `aborted` bucket/redacted outcome; they do not count as completed2xx transfers. No private account/job/reference/content becomes a metric label. The actual storage-only32MiB operator, fresh-process read and different-account denial are recorded in [the receipt](../../artifacts/workstreams/W8/takeover/20260930/private-artifact-storage.json). This exercised synthetic storage bytes, not a real job lease, source snapshot, domain export, complete C10 job or system-save flow.

Content's purpose pool/source-revoke and approved retention, all eight erasures, original growth key recovery, protected binary/call archives, post-erasure real reauthentication and restore/re-purge/reopen remain open.
