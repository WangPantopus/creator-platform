Apple billing continues separately, so provide subscription management while preserving immediate deletion. Google requires discoverable in-app and external web deletion for covered accounts; directing account creation through Pantopus does not establish an exemption. Google requires reporting generated offensive content from within the app. [Apple deletion](https://developer.apple.com/support/offering-account-deletion-in-your-app), [Google deletion](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en), [Google AI policy](https://support.google.com/googleplay/android-developer/answer/13985936?hl=en).

Prepare accurate app/developer identity, functional privacy/deletion/support URLs, moderation/contact procedures, sandbox review accounts with only synthetic data, and reviewer steps through sign-in → labeled AI → report → support/privacy → billing management. Do not submit accounts, final URLs or declarations until configured. Apple UGC moderation and explicit permission for third-party AI data sharing require actual implementation; consent must name configured processors. [Apple review guidelines](https://developer.apple.com/app-store/review/guidelines/).

Audit the actual signed archive and SDK dependencies for collected/shared data, tracking and required-reason APIs. Neither a placeholder privacy page nor a generated manifest proves accurate store declarations. Keep third-party SDK data paths in Apple privacy labels and Google Data safety, including off-device ephemeral processing. [Apple privacy labels](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy), [Apple manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files), [Google Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en).

## Installed Trust image inventory

The W8-owned Docker recipe uses pinned Node/pnpm, the frozen workspace lock and pnpm12.5.1’s dedicated deploy lock instead of the legacy resolver. It includes the deployed package manifest alongside production dependencies. [pnpm deployment documentation](https://pnpm.io/cli/deploy) describes dedicated lock behavior. The unchanged backend is typechecked and bundled before the non-root runtime stage; the recipe still excludes env/secrets, artifacts and source compiler tooling.

Run `node infra/containers/trust-sbom.mjs <exact-source-commit> <actual-image-digest>` inside the reviewed image, with no network or secret mounts. The command reads the physically installed pnpm package graph and Debian package inventory, fails for missing required dependency bindings and emits an unsigned CycloneDX1.5 operations inventory. It labels package-manifest hashes precisely; they are not full package-content signatures. Native Node/npm embedded dependencies, dynamically mounted integration bundles and remote services need their own inventories. The root npm SBOM command was actually attempted offline but misinterpreted the pnpm virtual store, reporting missing dependency development tools and workspace file paths; those results do not justify installing test tools in a production image. [npm SBOM documentation](https://docs.npmjs.com/cli/v11/commands/npm-sbom/) describes its project dependency formats.

Validate the resulting inventory against the official CycloneDX schema, pin its hash beside the actual source/image receipt, then obtain the configured release signer and approved vulnerability/license disposition. Neither a generated inventory nor BuildKit’s local unsigned provenance enables deployment or substitutes for a signed whole-service SBOM. The local Trust image remains separate from a canonical API/web image and reviewed same-revision staging.
