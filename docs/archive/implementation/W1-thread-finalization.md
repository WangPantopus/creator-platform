# Original held-thread finalization

W4's October 2 review found that the held-session bookend repeated a locking `assertCurrentSession` after the domain's last signature gate. The original bootstrap still locks the genuine current session and installs its transaction-local ID once. Repeated held bookends now use one plain metadata/clock query on the original client, full XID, PID, login, account/session GUC and original request context; they acquire no row lock and change no GUC.

`Database.finalizeHeldThreadBeforeCommit(scope, client, actualOwnerGate)` supplies ordering, never domain or signature authority. Register exactly once inside the original genuine held callback. Database awaits ordinary work, refuses unfinished owner operations, checks the original current session, then awaits the registered real owner gate. After it only JavaScript cleanup/pending checks and COMMIT occur; a refusal rolls back. A retained/copied scope, other client/request/session or replacement gate cannot register. The consumer remains responsible for its exact current consent/source/signature/expiry authority and for not starting unfinished work.

Ordinary callbacks retain their current-session bookends. Separately scoped host/job callbacks never gain this interactive capability. Actorless publication needs a separate early preparation and atomic final SQL cleanup/currentness source; this port does not replace its nonce or negative authority.
