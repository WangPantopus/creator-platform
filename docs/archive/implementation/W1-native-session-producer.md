# Native identity storage and request capture

The shipping Swift and Kotlin models use the configured API issuer for every credential reader. A normalized HTTPS origin (or the exact supported Debug loopback origin) determines the OS-backed namespace. Credentials with no provable legacy issuer require sign-in. Keychain/Keystore clear and replacement failures surface in the shell and fence all in-process feature readers; both identity and conversation cleanup are attempted before another account can be installed.

`FanSession.captureRequest(from:)` / `FanSession.captureRequest(from)` returns an immutable client from the model's actual stored credential, account, session and destination. Consumers check `isCurrent()` before each request/provider handoff and before applying results. Account replacement, credential rotation, logout initiation, purge, cancellation and away-and-back navigation invalidate old captures. A routine identity refresh does not invalidate an active capture. Server-side authorization remains authoritative; this port grants no permission or provider admission.

One-ID call destinations use the actual account-bound canonical route operation and validate its exact returned call/family before navigating. Missing or refused metadata displays Retry and Open Requests. A captured navigation result does not authorize joining. Existing owner call transport, permission and lifecycle integrations remain their own source.

Foreground polling stops while inactive. A one-use credential rotation finishes its exchange and guarded persistence even if the foreground read is cancelled (Android `NonCancellable`, Swift independent task). A 5xx/network failure preserves the account and saved credential rather than reporting logout. Local deletion failure requires a successful retry before installing another account. Account, Status and Ops can be reached without Fan enrollment; other canonical Fan destinations preserve enrollment.

The generated navigation helpers and copy use their canonical inputs. iOS Info.plist exposes the actual build API/link-host settings; the app refuses malformed schemes, authority, ports and destinations. Debug loopback does not prove production HTTPS/app association or domain ownership.

Qualification is recorded separately against the final source revision. Existing Swift checks previously passed during review, with unchanged three native references and tolerances. Early compilation found missing issuer construction and an overbroad Growth import; both were corrected before publication. Shipping compilation, effective configuration and personally operated device journeys are distinct qualifications. No new unit tests were added; no positive proof, passkey, call/provider or release acceptance is inferred from compilation.
