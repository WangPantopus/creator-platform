# Current and convergent Team invitations — October 6, 2026

The canonical identity invitation producer inserted a new invitation on every call, including for a pending creator. Studio checked for an existing invitation in a separate transaction, so direct callers and concurrent requests could create multiple pending invitations. Personally reproduced two concurrent direct requests creating two rows while the disposable creator was pending verification; retained those rows revoked as historical evidence.

The canonical producer now uses the same held original request/session and same-client creator denial checks as role editing, requires current verified/non-recovering creator ownership, and keeps the existing creator/team locks through the pending-invitation read and insert. Repeating the same role set while an invitation is pending returns its existing ID and expiry. Different roles or multiple legacy pending invitations return 409 and require explicit removal before a new selection. Studio always delegates to this producer rather than returning its own earlier snapshot. Missing current denial authority fails closed. No API schema, migration, privilege or delivery adapter changed.
