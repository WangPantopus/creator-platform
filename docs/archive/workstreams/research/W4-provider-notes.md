## Stripe Billing and version compatibility

- Explicitly pin the provider API version and align webhook endpoint/parser expectations. The research identified `2025-03-31.basil` as a significant invoice/subscription shape boundary. Raw HTTP uses `Stripe-Version`; an approved SDK integration must configure its supported API version. [Versioning](https://docs.stripe.com/api/versioning).
- On Basil and later, subscription billing periods belong to `items.data[].current_period_start/current_period_end`, not subscription-level fields. [Period migration](https://docs.stripe.com/changelog/basil/2025-03-31/deprecate-subscription-current-period-start-and-end).
- Retrieve all invoice lines and paid InvoicePayments with pagination; embedded lists may be incomplete. [Invoice](https://docs.stripe.com/api/invoices/object), [InvoicePayments](https://docs.stripe.com/api/invoice-payment/list), [InvoicePayment object](https://docs.stripe.com/api/invoice-payment/object), [invoice lines](https://docs.stripe.com/api/invoice-line-item/retrieve).
- Newer invoice subscription references are under `parent.subscription_details`; line item references under `parent.subscription_item_details`; configured prices under discriminated `pricing.price_details`. Pre-Basil top-level `payment_intent`, `subscription`, `subscription_item`, `price` assumptions cannot silently survive that migration. [Payment changes](https://docs.stripe.com/changelog/basil/2025-03-31/add-support-for-multiple-partial-payments-on-invoices), [parent fields](https://docs.stripe.com/changelog/basil/2025-03-31/adds-new-parent-field-to-invoicing-objects), [pricing fields](https://docs.stripe.com/changelog/basil/2025-03-31/invoice-pricing-configurations).
- Multiple products in one subscription share an invoice and currency; separate subscriptions remain separately billed. Removing an item with `proration_behavior=none` avoids the default automatic proration credit, but product cancellation/refund policy still needs explicit implementation. [Multiple products](https://docs.stripe.com/billing/subscriptions/quantities), [delete item](https://docs.stripe.com/api/subscription_items/delete), [cancel subscription](https://docs.stripe.com/api/subscriptions/cancel).
- Invoice-line amount/list price is not a universal refundable paid-cash allocation. Discounts, tax, customer balance, credits, partial payments, earlier refunds and out-of-band paid invoices require genuine payment/allocation accounting. Line-linked credit notes distinguish cash refund, linked existing refunds and customer balance credit. Never grant a balance credit and an independent cash refund for the same obligation. [Credit-note integration](https://docs.stripe.com/invoicing/integration/programmatic-credit-notes), [credit-note API](https://docs.stripe.com/api/credit_notes/create), [refund API](https://docs.stripe.com/api/refunds/create).
- Manual authorization windows vary by payment/network. Read genuine capture-before and preserve the architecture's safety margin. Signed notifications are deduped change signals; current provider truth drives reconciliation. [Manual capture](https://docs.stripe.com/payments/place-a-hold-on-a-payment-method), [webhooks](https://docs.stripe.com/webhooks).

## Apple StoreKit/App Store server

- Official server library verification checks signed transaction/notification/renewal data against Apple roots, environment, bundle and production App Apple ID. Configure proper credentials and online certificate checks as required. [Official library](https://github.com/apple/app-store-server-library-node), [SignedDataVerifier](https://apple.github.io/app-store-server-library-node/classes/SignedDataVerifier.html).
- Verified payload includes optional UUID `appAccountToken`, transaction/original transaction, configured product, bundle/environment, expiry/upgraded/revoked/ownership fields. Successful JWS verification does not by itself prove the requester's ownership of an optional account mapping; that application authorization requirement is an inference. Reject conflicting bindings and require an established owned path when absent. [Transaction payload](https://apple.github.io/app-store-server-library-node/interfaces/JWSTransactionDecodedPayload.html).
- Server current transaction/status lookup and notification reconciliation require App Store Connect key/issuer/key ID/bundle/environment configuration. Rebinding account tokens needs application authority, not a client-selected UUID. [Server client](https://apple.github.io/app-store-server-library-node/classes/AppStoreServerAPIClient.html).
- Existing StoreKit client imports the OS framework without requiring a third-party Swift package. Its compiled code is not purchase proof; current product IDs, genuine server verification, account mapping and sandbox system UI remain required.
