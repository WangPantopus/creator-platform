# WP 5.5: digest owner connections — 2026-10-09

The worker and adapters exist, but weekly and 72-hour outcomes are not connected in the stock server. This work records the exact connections and a real-server check; it does not claim the digest work package is complete. No aggregate counts, quiet-week results or consent have been invented.

## Existing pieces to connect

`growth/weekly-impact.ts` already scans closed Monday-to-Monday UTC windows, creates stable jobs and leases them, uses current owner task callbacks, and feeds `Retention.recordImpact`. `canonicalWeeklyImpactSource` accepts actual counts and uses `contentThanksWindow` with an owner-held current Thanks target. An unavailable owner must not become a zero count.

`growth/retention.ts` already schedules one activation job per creator/version for publication plus 72 hours, reads a current snapshot, records a completed result or marks a missing source blocked. `retryActivation` can requeue it when the owner is connected. `agent/growth-adapter.ts` already implements `agentActivationSource` and `relayAgentEvents`; `growth/canonical.ts` also has `relayAgentPublications`. Connect one publication consumer, not two competing acknowledgers. W2's other outbox events must remain pending for their own consumers.

The stock `apps/backend/src/server.ts` call to `configureGrowthForBackend` omits `weeklyImpactSource`, `activationSource`, `thanksPermission`, `weeklyImpactNotices` and the delivery provider. There are no callers of either publication relay. The default worker therefore cannot produce a genuine weekly or 72-hour result. This is a host connection gap, not a reason to replace the existing workers.
