## Run W7 locally

W7 isolated resources: API4107, web3007, disposable database55437/container `creator-platform-w7`; do not reuse other owners' databases or devices. Run backend from `apps/backend`:

```sh
QELVORA_GROWTH_DEVELOPMENT=true W7_ENCRYPTION_KEY=<64-hex-key-from-secret-management> W7_IDENTITY_API_URL=http://127.0.0.1:4101 PORT=4107 pnpm exec tsx src/modules/growth/development.ts
```

Set `W7_DATABASE_URL`/`W7_WORKER_DATABASE_URL` for non-owner roles. Optional `W7_IDENTITY_API_URL` points to W1's actual configured loopback session API. The runner validates supplied Bearer credentials and proxies only the reviewed identity capability/session/sign-in/refresh/logout/revoke/profile paths; it does not issue/store credentials. This lets native debug clients use the same base URL. Synthetic browser actors remain distinctly labeled and upstream public projections remain synthetic. The bridge requires explicit loopback HTTP with no credentials; the runner binds loopback and rejects production mode. In an isolated Next build/source copy, set `QELVORA_GROWTH_API_URL=http://127.0.0.1:4107`, `QELVORA_GROWTH_DEVELOPMENT=true`, and `QELVORA_API_URL` to W1 for sign-in; start installed Next with port3007. Shipping uses one integrated API and approved HTTPS `QELVORA_PUBLIC_ORIGIN`, rejecting credentials/query/fragment/non-root origins. No final domain is invented.

## Primary platform research

Checked September29,2026. APNs delivery is best effort; register current token at launch and separately inspect alert authorization. Use current-state-safe copy, short/zero expiry, and fetch current object status on open. Invalid topic/device/unregistered responses revoke tokens; acceptance is not a delivery receipt. [Apple registration](https://developer.apple.com/documentation/usernotifications/registering-your-app-with-apns), [Apple sending](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns), [Apple responses](https://developer.apple.com/documentation/usernotifications/handling-notification-responses-from-apns).

FCM supports registration evolution; track freshness, handle token replacement/unregistered errors, and require Android13+ notification permission. Zero TTL discards undeliverable messages. Quota retries must honor provider delays/backoff. [Firebase registration lifecycle](https://firebase.google.com/docs/cloud-messaging/manage-tokens), [lifespan](https://firebase.google.com/docs/cloud-messaging/customize-messages/setting-message-lifespan), [errors](https://firebase.google.com/docs/cloud-messaging/error-codes).

Optional subscription email needs a visible unsubscribe and RFC8058 one-click POST without session/origin/redirect/confirmation dependency. Provider DKIM must cover unsubscribe headers. [RFC8058](https://datatracker.ietf.org/doc/html/rfc8058#section-3.1), [Gmail sender guidance](https://support.google.com/mail/answer/81126).
