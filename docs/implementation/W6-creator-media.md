## Authority and publication

- `CreatorMediaAuthority.policy(scope,objectId,purpose,operation,client)` checks the actual current object, purpose/consent and approved limits/retention. Source/interview consent, ownership/license, sanctioned processors and candidates remain W2 authority. No transcript or synthetic enablement is implied.
- `denied(scope,client)` must returnfalse explicitly. `currentAssetRead(scope,objectId,asset,client)` must returntrue explicitly. Owners require current object/purpose/role authority; audience reads additionally require the exact asset/version/SHA in the current published revision, genuine publication and current audience. Retain object/grant locks before asset locks through commit. W6 rejects a changed asset snapshot after acquiring its lock.
- `evidence(scope,client,objectId,assetId)` verifies W1's issued creator scope/current session/verification in the same client and returns `{assetId,version,sha256,bytes,mimeType,durationMs}` for immutable processed media. W5 reviews and signs complete snapshots outside the immutable document as `command.content.mediaEvidence`, locking assets in deterministic order.
- W5 consumes the genuine W1 named act once, then calls `attachPublication(scope,client,objectId,signedActId,command,evidence[])` in that same transaction. W6 checks the exact consumed act/publication and each complete snapshot. Only human_note/post_photo may use this content-publication path. Source/interview require their own reviewed purpose authority.
- `readyForPublication(scope,client,objectId,evidence,signedActId)` checks the current signed publication association, the same complete snapshot and genuinely verified C2PA provenance. `publicationMatches(scope,client,objectId,signedActId,evidence)` supplies W5's mandatory same-client publication binding without re-entering object/asset read policy. Its evidence includes bytes, MIME type and duration as well as asset/version/SHA. W5 owns `media_pending`/current revision finalization and delivery. No fan publication occurs merely because processing reachedready.
- C2PA decoration changes only the delivered output and provenance. The immutable processed file, version/SHA/bytes/MIME/duration remain unchanged; `provenance.fileSha256` identifies decorated delivery. Reuse links a new genuine publication to the same permitted processed snapshot without replacing its original recording occurrence. Audience playback and publication readiness require provenance coherent with the exact asset, owner, object, version, processed bytes/MIME/duration and original act. The draft SQL makes identity, processed evidence, original occurrence and terminal tombstones immutable, and permits fan reads of publication associations only through an RLS-visible ready asset. Each inserted association must match a genuinely consumed, unwithdrawn act and its exact processed evidence.
- `withdraw(scope,client,objectId)` invalidates a separate private `access_epoch`; old tickets/streams stay invalid even after republishing. W5 immediately denies current read through its withdrawn/draft policy. Withdrawal does not erase media allowed in a legitimate future revision. Owner `revoke` and approved expiry/privacy cleanup use distinct durable tombstones and delete every retained variant.

W3's thread-specific `MediaService.publishedRecording(scope,client,evidence)` validates the already-consumed reply signature/C2PA/current purpose before immutable association. W3 holds its thread lock first and does not consume the act a second time or attach unsigned text.

## Web host composition

`CreatorVoiceRecording` from `apps/web/features/media/VoiceRecorder.tsx` accepts `{creatorId,objectId,creatorName?,onReady?,beforeDiscard?}`. The object is an actual saved W5 draft. Recording is private until explicit upload, and Note duration is bounded at 60 seconds. `onReady(asset,evidence)` supplies a ready human Note asset and validated complete `ProcessedMediaEvidence` to a client Studio host; W5 saves the attachment and signs its complete current Note. It never uses the thread signing endpoint. `beforeDiscard(assetId)` lets that host remove an attached draft item before W6 revokes the upload. Callback props belong in a client host; server components pass only serializable IDs/name.

`CreatorVoicePlayer` from `apps/web/features/media/VoicePlayer.tsx` accepts `{asset,creatorId,objectId,creatorName,fanId?,transcript?,time?}`. Owners omit fanId. Audience hosts supply only a genuine W1-authorized fan/thread context. It validates the Note/object/ready-audio binding, uses exact same-origin cookie playback routes, and stops on unavailable or changed current access. No transcript or publication time is invented. Changing the family/object/asset/version/SHA remounts the player/recorder and aborts stale work. Processing polls do not overlap, upload/discard retain the existing unknown-response/key recovery, and multiple recorders use independent accessible headings.

The additive W6 capability `creatorMediaAvailable` requires both creator-media service and the issuer callback; it is false in the current unconfigured host. W1 owns root/session/BFF composition; W5 owns draft/publication callbacks. These components are compiled/linted integration producers, not an observed human microphone, passkey, publication, provider or hardware acceptance.

## Recovery and account privacy composition

Original uploads remain bounded to256 MiB and one hour at the transport ceiling, with purpose policy applying tighter limits. Every chunk advances only from a matching acknowledged offset; signed upload URLs must match the exact asset upload path and origin. Revoked/deleted or unrecognized states cannot resume.

This SQL is still reserved/unapplied and not a database acceptance result.
